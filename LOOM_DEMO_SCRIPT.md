# Loom Demo Script

## Introduction (30-45 seconds)

"Today I’m showing an AI Project Stand-up & Risk Assistant built to solve a very specific problem: managers lose time collecting fragmented updates and identifying blockers. The product focuses on one workflow deeply—structured project updates, AI analysis, risk detection, and manager review."

## Explain the Solution (45-60 seconds)

"The solution makes updates more consistent, helps the AI extract tasks and blockers from the update, remembers historical context so recurring issues are visible, and gives managers a concise operational dashboard and recommended actions."

## Show Employee Update Submission (45-60 seconds)

"I’ll now submit an employee update using the standard form. The employee enters their name, team, project, completed work, today’s focus, blocker, dependency, and optional context. This keeps reporting consistent and short."

## Show AI Analysis (45-60 seconds)

"The system runs AI analysis against this update. It extracts structured information, any blockers, risk level, and a recommendation. We separate facts and AI inference so the manager can see what is grounded in the update and what is a recommendation."

## Show Blocker and Risk Detection (45-60 seconds)

"Here we can see the blocker detection and assigned risk. For example, a dependency on database access or customer data is flagged as a blocker and the system explains the impact and recommended action."

## Show Historical Context / Recurring Blocker (45-60 seconds)

"This is especially important because the AI remembers previous updates. If the same blocker repeats over multiple days, the risk is escalated and the manager sees that it is now a recurring unresolved dependency."

## Show Human Validation (45-60 seconds)

"Managers are not forced to trust the AI. Each AI result can be confirmed, edited, rejected, or marked as resolved. That human validation step is critical for reliability and adoption."

## Show Manager Dashboard (60 seconds)

"Now I’ll move to the manager dashboard. It shows updates received, completed work, active blockers, and project health. The manager sees the overall picture in seconds instead of manually consolidating updates from multiple channels."

## Show AI Copilot (45-60 seconds)

"The copilot can answer operational questions such as which projects are at risk, who is blocked, and which dependencies need immediate attention. This keeps the workflow grounded in the application’s data and reduces manual synthesis."

## Show Leadership Metrics (45-60 seconds)

"The leadership view includes adoption rate, completion rate, blocker confirmation rate, AI correction rate, and manager time saved. These metrics are demo-illustrative and help show how the process can be measured in a real operating environment."

## Explain Stage 2 Improvements (45-60 seconds)

"The redesigned process addresses adoption, standardization, AI accuracy, and reliable measurement. These are the specific problems that emerge after a pilot. The design adds structure, validation, and metrics without requiring new software purchases or additional hiring."

## Explain Architecture and Another Week (45-60 seconds)

"The architecture is simple: structured intake, AI normalization, analysis, review, dashboard, and metrics. If we had another week, we would expand provider integration, persist reviews in SQLite, and refine trend analysis and exports."

## Closing (15-20 seconds)

"This prototype shows the core story clearly: AI helps managers reduce status collection overhead, detect blockers sooner, track recurring issues, and make better decisions with the right human review in the loop."
